# ACONSU system audit, 15 October 2026

What was audited: the code on `main` plus the chapter sign-in change that is on its own branch and not yet
merged (`5663fe9`, "Leaders choose their chapter when they sign in").

## How it was done

| Check | What was run |
|---|---|
| Automated tests | `node test/smoke.js` (1,502 checks) and `node test/ux.js` (53 checks, real browser). All pass. |
| Dependencies | `npm audit` and `npm outdated`. |
| Secrets | Searched every tracked file for keys, connection strings and private keys. |
| Routes | Parsed all 319 routes, listed those with no guard named on them, and read every write among them. |
| Live probes | Started a production-mode copy and probed exposed paths, protected endpoints, headers, caching, compression, cookies, CORS and error handling. |
| Browser crawl | Loaded 46 pages (the offline page left out), signed out and as a member, light and dark, at phone width (152 page loads) with axe-core, console capture, page weight and tap-target measurement. |
| Code reading | Data-access layer, sign-in and reset flows, file serving, scheduled jobs, Android manifest, CI, privacy page against the code. |

**Not checked, because it lives outside the repository:** the live Render settings (plan, region, environment
variables), the MongoDB Atlas plan and its backup setting, any Cloudflare or DNS settings, the live site, and
behaviour on a real Android phone. Several findings below say "check this in the dashboard" for that reason.

## What is already good

- No secrets in the repository. Production refuses to start with the default admin password or session secret.
- No known vulnerabilities in the packages the live app uses (`npm audit --omit=dev`: 0).
- Security headers are all present: HSTS, CSP, no framing, no MIME sniffing, same-origin policies. Cookies are
  `HttpOnly; Secure; SameSite=Lax`. No CORS.
- Sensitive paths (`.env`, `.git`, source files, `node_modules`) are not served. Every protected API answered 401.
- Sign-in errors are uniform, the password reset token is hashed and expires in an hour, and a reset request
  never reveals whether an account exists.
- Chapter separation holds: 46 of 56 record types carry an indexed chapter, the other 10 are national on purpose, and
  I read 9 handlers that look records up by id with no chapter filter. Each one checks the chapter inside the handler.
- File serving: private categories (receipts, profile photos) are refused as "not found", and anything that is not a
  picture, audio, video or PDF is sent as a download that cannot run.
- Accessibility: 152 page loads, zero console errors, and axe found only 3 kinds of issue (below).
- No em dashes in anything a person reads, and no gradients in the app's stylesheets.

## Findings, in the order to fix them

Effort: **S** is under a day, **M** is a few days, **L** is a week or more.

### High

| # | Finding | Evidence | What to do | Effort |
|---|---|---|---|---|
| H1 | **No backup or restore plan.** The README says Atlas gives "automatic backups". A free (M0) Atlas cluster has none. Members, the finance ledger and shepherding notes are all in that one database. | No `mongodump`, export script or restore note anywhere in the repo. | Check the Atlas plan today. If it is free: schedule an encrypted export to storage you control, or move to a paid size that includes backups. Write the restore steps down and rehearse them once. | S to M |
| H2 | **The privacy page promises more than the app does.** It says people can have their account and personal information deleted. | Admin "delete member" removes the member record and photo only. 21 other places hold a member id: prayer requests, chat, event registrations, attendance, alumni profile, welfare entries, the linked leadership login. There is no self-service delete or export. | One "erase this member" routine used by both the admin button and a self-service button: remove or anonymise everywhere, revoke their sessions, close a linked leadership login. Add a data export. Test it against every record type. | M |
| H3 | **Every list is read whole, and nothing is ever purged.** | 190 calls to `repo.getAll`; the data layer has no limit, sort or projection. `GET /api/notifications` loads every notification for the chapter, sorts them in memory and returns 40. Measured in a browser, every page asks for it twice and the home page four times, for guests and members alike. No old record is ever deleted. | Add limit, sort and projection to the data layer. Fix notifications first (database-side limit plus an unread-count query). Add retention for notifications, SMS logs, chat and contact messages. Matters most on a 512 MB host. | M (notifications S) |
| H4 | **The Android app probably cannot use the microphone in ACONSU Rooms.** | `meet.html` asks for `getUserMedia({ audio: true })`. The manifest declares `CAMERA` but not `RECORD_AUDIO`. Also `allowBackup="true"`. | Declare `RECORD_AUDIO` (and `MODIFY_AUDIO_SETTINGS`), set `allowBackup="false"`, test Rooms on a real phone, update the Play Data safety form (it does not mention camera or microphone). | S |
| H5 | **Leadership accounts are protected by a password alone.** They reach finance, welfare and shepherding records. | Minimum password length is 8, no second factor, per-IP rate limit only. | Add an authenticator-app second step for leadership accounts, raise the minimum to 12, add a per-account lockout. | M |

### Medium

| # | Finding | Evidence | What to do | Effort |
|---|---|---|---|---|
| M1 | **Production safety depends on one dashboard setting.** HSTS, secure cookies, the default-password refusal and hidden error details all key off `NODE_ENV=production`. | No `render.yaml`; the value is only set by hand. | Add `render.yaml`, and make `/api/health` report whether production mode is on. | S |
| M2 | **Scheduled work runs inside the web process.** Announcements, birthdays, onboarding and retention checks use `setInterval`. | On a sleeping free host they run late. With two instances they could send twice (no lock). | Keep the app awake with a free uptime pinger on `/api/health`, or use a paid plan. Add a database lock before ever running two instances. | S |
| M3 | **Pages are heavier than they need to be.** | No compression. Assets are sent `max-age=0`. The home page is 595 KB over 30 requests, including a 313 KB splash PNG. The larger app icons are 160 to 270 KB each. `admin.js` is 152 KB. | Turn on `compression`, cache fonts, icons and images for a long time, shrink the PNGs. Cuts data cost on phones in Ghana. | S |
| M4 | **Three phone layout and contrast bugs.** | Discover tiles run 15 px past the screen edge and Profile's quick links also cause sideways scroll at 390 px. Discover search text is black on dark purple in dark mode (contrast 1.24, unreadable). The notification bell is 22 x 22 px on every page. | Fix each. All small CSS changes. | S |
| M5 | **Unknown URLs answer HTTP 200.** | The catch-all sends the 404 page without a 404 status, so `/anything` looks like a real page to search engines and monitors. | Send `404`. One line. | S |
| M6 | **Chapter checks are manual.** 25 by-id lookups rely on a check written in each handler. | All 9 I read are correct. A forgotten check in future code is a cross-chapter leak. | Make the data layer require an explicit chapter filter for the 46 chapter-scoped record types, and add a test that fails if a route skips it. This is the real answer to "overlap" between chapters. | M |
| M7 | **A password reset leaves other sessions signed in.** | Leadership sessions are revoked on a change; members' are not. | Revoke a member's sessions on reset and on password change. | S |
| M8 | **The CSP allows inline scripts.** | `script-src 'self' 'unsafe-inline'`. | Move inline scripts into files, then drop `'unsafe-inline'`. | M |
| M9 | **Approved alumni photos will be copied into public git history.** | The site refresh commits `site/images/alumni` to a public repository. Deleting a photo later does not remove it from history. | Publish the site data without committing it, or keep photos in file storage. Decide before the first alumnus is approved. | M |
| M10 | **Dependencies are a major version behind, and Node 20 is allowed.** | `engines` is `>=20.9.0` (Node 20 reached end of life in April 2026). Express 4, Mongoose 8, helmet 7, bcryptjs 2, express-rate-limit 7. 3 moderate advisories, all in the Android build tooling, none in the live app. | Set `engines` to Node 22. Plan the major upgrades one at a time, with the tests as the net. | S to M |
| M11 | **CI only runs half the tests.** | The browser suite (53 checks) is not in CI; `npm audit` ends in `|| true`; no linter. | Add the browser suite as a CI job, make the audit fail on high severity, add a linter. | S |

Found while fixing, and fixed too:

- **Every file on every page cost a database lookup.** Static files were served after the session was read, so a page's thirty-odd fonts, icons and scripts each loaded the session from MongoDB. They are now served before it.
- **A signed-in member was asked "Choose your ACONSU chapter" on any new phone** as soon as a second chapter existed, before anything drew, and their answer was then overruled by their account. Who is signed in is now checked first.
- **The test database answered instantly**, which hid any "count, then write" race from the suite. It can now be slowed for a test that needs it.

Not touched, because they are bigger than a small fix: H2 (erase and export a member), H5 (second step for leaders), M6 (chapter checks by default), M8 (inline scripts), M9 (alumni photos in public history), L6 (splitting `server.js`), L8 (the October theme is yours to enter).

## Fixed since (30 October)

| Item | What changed, and the evidence |
|---|---|
| H2 | Fixed. One routine, `lib/eraseMember.js`, is used by the admin's Delete member and by a new **Delete my account** on the profile page: 24 record types holding a member id are each deleted, kept without the name (money, Sunday marks) or have the person taken off them; records sent without an account are matched by email or phone; a linked leadership login is closed; every session ends, in memory and in the session store. **Download my data** gives everything back as one file. Both re-ask for the password and are rate-limited. Evidence: `test/privacy.js`, which also fails if a schema gains a member-id field the routine does not cover (checked by removing one: it fails). |
| H3 (retention) | Notifications, SMS records and contact messages are deleted after 12 months and chat after 2 years by a daily job (`lib/retention.js`), configurable per kind, under a database lock so two copies of the app never both run it (`lib/jobLock.js`). The privacy page states the same numbers and a test checks they agree. Paging everywhere is still to do. |
| L6 (start) | A code checker (ESLint, `eslint.config.js`, `npm run lint`) now runs in CI as **Code check**. It looks for mistakes only, never style. On its first run it found a real one: two functions in `server.js` shared the name `coordinatorMemberIds`, the later silently replaced the earlier, and so the push telling a Coordinator "an executive is waiting for an account" had never been sent. Fixed, with a smoke-suite check that it now goes out. It also removed a handful of unused leftovers. Splitting `server.js` itself is still to do. |
| CI | The browser suite now fails the build when it fails, instead of only reporting. It has been passing on GitHub's machines on recent pull requests (one of them only after a re-run), and passed twice in a row locally (63 of 63 checks each time) before the switch. |
| M9 | Fixed before any alumnus was approved, so there is no history to clean (`git log -- site/images/alumni` is empty). The site refresh no longer commits the alumni photos, the theme flyers or the feed: they are fetched at every publish and uploaded with the site, and `.gitignore` keeps the photo folders out. Tests: the smoke suite's site-copy section (fresh checkout, hostile live copy, both out of reach) and the workflow checks. |
